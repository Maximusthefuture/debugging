# Отладка Java через Java Debugger MCP

Плагин расширяет встроенный MCP Server IntelliJ IDEA. Отдельный сервер не нужен;
инструменты работают с debug-сессией, видимой в окне Debug IDE.

## Предпосылки

- В IDEA включён MCP Server, установлен плагин Java Debugger MCP, агент перезапущен после установки.
- Если `jdebug_sessions` пуст — попроси пользователя запустить конфигурацию в Debug
  (кнопка Debug или `jdebug_start {"configurationName":"Точное имя"}`).
- `sessionId` можно опускать, только если жива ровно одна сессия. При нескольких проектах
  передавай `projectPath` — стандартный аргумент встроенного сервера.
- Номера строк — с единицы, `frameIndex` — с нуля. Пути в `jdebug_breakpoint` —
  абсолютные или относительно корня проекта.

## Базовый цикл отладки

1. `jdebug_sessions` → выбери `sessionId` (при нескольких уточни, какая нужна).
2. При необходимости `jdebug_breakpoint {"filePath":"...","line":N}` — установка или удаление.
3. `jdebug_control` с действием `resume|pause|stepOver|stepInto|stepOut|stop`.
4. **После resume/шага дождись `state: suspended` через `jdebug_status`** с ограничением
   числа попыток. Отправка команды — не подтверждение остановки. Если программа ждёт
   внешнего запроса — скажи пользователю, какое действие воспроизведёт проблему.
5. При `suspended`: `jdebug_stack` → выбери `frameIndex` → `jdebug_variables`,
   при необходимости `jdebug_evaluate`. Перечитывай стек после каждого шага/продолжения.
6. Стек относится к активному потоку; переключение потока — только вручную в окне Debug.

## Чтение логов

Начинай с `jdebug_search_logs` — поиск выполняется в IDE, в контекст попадают только
ограниченные фрагменты:

```text
jdebug_consoles {}
jdebug_search_logs {"consoleId":"ID","query":"Exception","maxMatches":5,"contextLines":1,"maxChars":3000}
```

- Для живой сессии вместо `consoleId` допустим `sessionId`. Остановка на breakpoint не нужна.
- Проверяй `scanTruncated`: нулевой результат при усечённом скане не доказывает отсутствие
  совпадений. Для нового вывода ограничивай поиск через `afterCursor`.
- Если фрагментов недостаточно — `jdebug_logs {"consoleId":"ID","maxLines":200}`.
  Учитывай `truncated` и `pendingOutput`: это снимок буфера IDE, не полная история.
- После завершения процесса читай по `consoleId`, пока вкладка открыта. `idea.log` не подменяет логи приложения.

## Логи после вызова метода

```text
jdebug_log_cursor {"sessionId":"ID"}          → consoleId + cursor
jdebug_evaluate {"sessionId":"ID","expression":"service.process()"}
jdebug_logs_since {"consoleId":"ID","cursor":"КУРСОР","waitMs":10000,"contains":"done"}
```

Фиксируй курсор ДО вызова метода. Проверяй `matched/timedOut/truncated/reason`;
продолжай с возвращённого курсора, не повторяя вызов Java-метода. Инвалидированный курсор —
сообщи о возможной потере логов и создай новый. Не приписывай весь вывод консоли одному
методу без дополнительных доказательств.

## Правила безопасности и этикета

- Не вызывай методы с побочными эффектами без необходимости; после таймаута вычисления
  не повторяй его автоматически. Таймаут не отменяет уже исполняющийся Java-код.
- Не удаляй чужие breakpoint'ы. Запомни свои и удали их после работы.
- Выводы подкрепляй наблюдаемыми значениями, файлом и строкой. Не считай выражение
  успешно вычисленным, если сессия изменилась или инструмент вернул ошибку.
- `jdebug_start` возвращает `submitted: debug` — это подтверждение отправки, а не
  появления сессии. Дождись её через `jdebug_sessions`; не повторяй запуск автоматически
  (сборка/подключение отладчика занимают время). Имя конфигурации — точное и уникальное.

## Лимиты инструментов

| Инструмент | Ключевые ограничения |
| --- | --- |
| `jdebug_logs` | `maxLines` 1–2000, `maxChars` 1–100000 |
| `jdebug_logs_since` | `waitMs` 0–30000, `maxChars` 1–100000 (умолч. 20000) |
| `jdebug_search_logs` | подстрока ≤ 256 символов, до 20 фрагментов, фрагмент ≤ 2000 символов, `maxScanChars` до 5 000 000 |
| `jdebug_evaluate` | ожидание ответа отладчика ≤ 10 с на операцию |
| `jdebug_variables` | дочерние значения ограничены параметрами вызова; именованные группы не раскрываются |
